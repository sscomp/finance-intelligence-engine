# M8 — 營運驗收

## Problem / Context

Phase 5 M2–M7 完成了所有程式碼交付與工程驗證，但缺少營運層面的驗收：系統在連續多日的真實資料環境下，是否能穩定產出一致的投資組合決策？M8 是一個 wall-time gate，需要連續 7 天的 live 觀測。

## Decision

### Portfolio Shadow-Run 擴充

建立 `phase3/pipeline/portfolio_shadow_run.py` 模組與 `portfolio-shadow-run` CLI 子命令（完全 additive，不修改既有的 `shadow-run`）。此擴充將歷史 artifact 的投資組合決策重放，驗證配置建議的穩定性。

### 7-Day Observation Window

連續 7 天每日執行 `portfolio-run` 對比真實 morning-brief artifact，使用 R1–R7 調解檢查：

| 檢查 | 內容 |
|------|------|
| R1 | Artifact 存在且可讀 |
| R2 | Pipeline 執行成功（exit code 0） |
| R3 | jobs.json 語意配置不變（scoped signature，排除 volatile 欄位） |
| R4 | 確定性：重放結果 byte-identical（modulo generated_at） |
| R5 | 分數非預設值（有真實信號支撐） |
| R6 | 無非預期失敗 |
| R7 | 報告產出有效 |

### R3 Scoped Signature

R3 最初使用 whole-file SHA-256 比較 jobs.json，但 jobs.json 是共享排程器狀態檔，任何並發 cron 觸發都會改變 volatile 執行時欄位。修正為 scoped signature，排除 12 個 volatile 欄位（`last_run_at`、`next_run_at`、`state`、`fire_claim` 等）及嵌套的 `repeat.completed`，僅比較語意/配置欄位。

## Consequences / Trade-offs

- **正面**：營運驗收提供系統在真實環境下的穩定性證據
- **取捨**：7 天的 wall-time 要求無法加速；需要排程器支援每日觀測
- **R3 修正**：scoped signature 更精準但更複雜，需要維護 volatile 欄位清單

## Validation / Evidence

- Portfolio shadow-run extension：1575 tests PASS（16 new + 1559 regression）
- 獨立審查：PASS WITH CAVEATS（3 個 caveats，皆 non-blocking）
- Day-1 觀測：exit code 0, deterministic=true, R1-R6 PASS
- R3 scoped validation：27 targeted tests PASS，Day-2 re-adjudicated FAIL→PASS

## Known Incidents

1. **Watch scheduler root cause fix（2026-08-16）**：觀測腳本的 `no_agent` script 欄位使用了命令行而非檔案路徑，導致 6 個 one-shot job 全部失敗。修正後重新註冊。
2. **R3 nested repeat.completed（2026-08-21）**：scoped signature 未排除 `repeat.completed` 嵌套欄位，導致 Day-3/Day-4 false-positive。修正後排除。
